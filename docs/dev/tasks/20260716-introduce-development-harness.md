# 개발 하네스 도입

## 작업 목적

basic-harness의 문서 기반 개발 하네스를 cafe 프로젝트에 맞게 최소 구성으로 도입한다. 개발자가
실제 작업 명령과 데이터베이스 환경을 쉽게 확인하고, 코딩 에이전트가 변경 위험에 맞는 절차와
검증을 일관되게 사용하도록 한다.

## 변경 범위와 계획

- 변경할 영역: 루트 작업 규칙, 작업 실행 가이드, 프로젝트 프로필, 작업 기록 양식과 안내
- 변경하지 않을 영역: 애플리케이션 소스 코드, Gradle 설정, Git 설정과 기록,
  API·DB·정책 문서
- 구현 방향: basic-harness의 공통 규칙은 유지하고 cafe의 브랜치, 사용자, 데이터베이스와 검증
  명령을 프로젝트 프로필에 기록
- 검증 방법: basic-harness 전용 참조와 문서 공백 확인, Git 변경 범위 확인, Gradle 테스트와 빌드

## 변경 결과

- 핵심 변경: cafe용 최소 하네스와 프로젝트 실제 값을 기록하는 프로필 추가
- 변경 파일: `AGENTS.md`, `docs/agent-workflow.md`, `docs/project-profile.md`,
  `docs/templates/task-log.md`, `docs/dev/tasks/README.md`, 이 작업 기록

## 검증과 남은 사항

- 실행한 검증과 결과:
  - 문서 파일 목록, 기본 하네스 참조와 줄 끝 공백을 정적으로 확인
  - `./gradlew test`: 성공. Spring 컨텍스트와 개발용 H2 데이터소스 기동 확인
  - `./gradlew build`: 성공. 테스트, 검사와 애플리케이션 패키징 완료
- 실행하지 못한 검증: 없음
- 남은 제한사항과 사용자 조치:
  - Gradle 10과 호환되지 않을 수 있는 폐기 예정 기능 경고가 있으므로 의존성이나 Gradle을
    올리기 전에 `--warning-mode all`로 원인을 확인해야 함
  - 저장소에 아직 첫 커밋이 없어 기존 프로젝트 골격과 이번 하네스 파일이 모두 미추적 상태
  - 브랜치 보호·병합 방식, 커밋 메시지 형식과 운영 배포 환경은 아직 미정
