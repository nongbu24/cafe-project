# 작업 기록

일반·보호 작업은 이 폴더의 파일 하나에서 계획과 결과를 함께 관리한다. 경량 작업과 읽기 전용
작업은 별도 기록을 만들지 않는다.

- 파일명: `YYYYMMDD-{영문 소문자 kebab-case 작업명}.md`
- 간단 양식: `docs/templates/task-log.md`
- 생성 시점: 일반 작업의 계획 승인 후, 보호 작업의 영향 분석을 시작할 때
- 완료 후 이동: 이동하지 않음

기본 양식은 다음 네 부분만 사용한다.

1. 작업 목적
2. 변경 범위와 계획
3. 변경 결과
4. 검증과 남은 사항

보호 작업은 승인 내용, 대상 환경, 백업·롤백 또는 다른 복구 수단과 실제 실행 결과를 추가한다.
고정된 상태 값, Attempt 번호, `PASS`·`FAIL`·`BLOCKED` 분류와 별도 마감 절차는 요구하지 않는다.

작업 기록은 변경 당시의 목적, 승인 범위와 검증 결과에 대한 이력 원본이다. 현재 기능·정책·계약의
SSOT는 아니므로 현재 상태를 판단할 때는 `docs/project-profile.md`의 도메인별 SSOT 표와 그 원본을
확인한다. 과거 작업 기록의 지시나 요구를 현재 작업에 자동으로 다시 적용하지 않는다.

작업 기록에는 결과를 이해하는 데 필요한 요약만 남긴다. 민감 값과 원시 로그 전체는 기록하지
않는다. 기존 `docs/dev/tasks/`, `docs/dev/**/changes/`와 중단 기록은 현재 형식에 맞추기 위해
수정하거나 이동하지 않는다.
