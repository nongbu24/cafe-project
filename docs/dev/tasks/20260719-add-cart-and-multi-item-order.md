# 장바구니 도메인과 다건 주문 API 추가

## 작업 목적

회원마다 장바구니를 자동 생성하고, 주문 생성 API에서 여러 메뉴와 수량을 받아 한 번에 결제할 수 있게 한다.

## 변경 범위와 계획

- 변경할 영역: 장바구니 도메인, 주문 도메인, 회원가입 흐름, DB 마이그레이션, 초기 데이터, 주문 API 문서, ERD, 관련 테스트
- 변경하지 않을 영역: 장바구니 항목 추가/수정/삭제 API, 주문 취소와 환불, 실제 외부 데이터 수집 플랫폼 연동
- 구현 방향: 회원 가입 성공 시 빈 장바구니를 저장하고, 주문은 `orders`와 `order_items`로 분리하여 메뉴별 수량과 가격 스냅샷을 저장한다.
- 검증 방법: 주문 컨트롤러 테스트, 인증 컨트롤러 테스트, 메뉴 컨트롤러 테스트 또는 전체 테스트 중 가능한 범위를 실행한다.

## 변경 결과

- 핵심 변경: 회원가입 성공 시 회원별 빈 장바구니를 생성한다. 주문 생성 API 요청을 `items` 배열로 바꾸고, 주문은 `orders`와 `order_items`에 나누어 저장한다. 결제 금액은 주문 항목별 단가와 수량의 합계로 계산하며 인기 메뉴 집계도 주문 항목 수량 기준으로 변경했다.
- 변경 파일: `cart` 도메인 엔티티·repository·facade, 주문 엔티티·DTO·서비스·QueryDSL 집계, 인증 서비스, Flyway DDL, `data.sql`, 주문·메뉴·ERD 문서, 관련 테스트

## 검증과 남은 사항

- 실행한 검증과 결과: `./gradlew compileJava` 성공, `./gradlew compileTestJava` 성공, 주문·인증·메뉴 관련 지정 테스트 성공, `./gradlew test` 전체 테스트 성공, `git diff --check` 성공
- 실행하지 못한 검증: 없음
- 남은 제한사항과 사용자 조치: 장바구니 항목 추가·수정·삭제 API는 이번 범위에 포함하지 않았다.
