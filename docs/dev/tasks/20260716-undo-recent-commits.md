# 최근 커밋 두 개 취소

## 작업 목적

ERD·API 명세 커밋은 유지하고 이후에 생성된 Spring Boot 초기화 및 개발 작업 규칙 커밋을 취소한다.
커밋에 포함됐던 파일 변경은 작업 폴더에 보존한다.

## 변경 범위와 계획

- 승인 내용: 사용자가 `d64b876`은 유지하고 최근 두 커밋 `14f92a5`, `f41b4a5`를 취소하도록 승인
- 대상 환경: 로컬 `dev` 브랜치
- 실행 방법: `git reset --soft d64b876`
- 예상 영향: `dev` 브랜치의 HEAD가 `d64b876`으로 이동하고 최근 두 커밋의 변경은 스테이징 상태로 남음
- 복구 방법: Git reflog에서 기존 HEAD `f41b4a5`를 확인한 뒤 필요하면 해당 커밋으로 브랜치를 복구
- 검증 방법: 최근 커밋 로그, HEAD와 스테이징·작업 폴더 상태 확인

## 변경 결과

- 핵심 변경:
  - `dev` 브랜치의 HEAD를 `d64b876`으로 이동했다.
  - `f41b4a5`, `14f92a5` 커밋을 브랜치 기록에서 제거했다.
  - 두 커밋에 포함됐던 파일 변경은 삭제하지 않고 스테이징 상태로 보존했다.
- 변경 파일: 파일 내용은 되돌리지 않았으며, 이 보호 작업 기록만 새로 작성했다.

## 검증과 남은 사항

- 실행한 검증과 결과:
  - `git log`에서 HEAD가 `d64b876`이고 해당 커밋만 남은 것을 확인했다.
  - `git status --short`에서 최근 두 커밋의 파일이 스테이징 상태로 보존된 것을 확인했다.
  - `git reflog`에서 기존 HEAD `f41b4a5`와 이전 커밋 `14f92a5`를 확인했다.
- 실행하지 못한 검증: 파일 내용을 변경하지 않았으므로 애플리케이션 테스트는 다시 실행하지 않았다.
- 남은 제한사항과 사용자 조치: 보존된 변경은 아직 스테이징 상태이며, 이 작업 기록은 미추적 상태다.
