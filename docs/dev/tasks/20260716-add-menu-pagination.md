# 메뉴 목록 페이지네이션 구현

## 작업 목적

메뉴 목록 조회 API가 많은 메뉴를 한 번에 반환하지 않도록 페이지 단위 조회를 지원한다.

## 변경 범위와 계획

- 변경할 영역: 메뉴 Repository·Service·Controller·응답 DTO, 입력 오류 응답, API 문서와 통합 테스트
- 변경하지 않을 영역: 메뉴 데이터 구조와 초기 데이터 100건, API 경로
- 구현 방향: 페이지는 0부터 시작하고 기본 크기 10, 최대 크기 100으로 제한하며 메뉴 ID 오름차순으로 조회한다.
- 검증 방법: 기본값·페이지 이동·최대 크기·잘못된 요청 통합 테스트, 전체 테스트, `git diff --check`

## 변경 결과

- 핵심 변경:
  - 메뉴 목록을 메뉴 ID 오름차순으로 페이지 조회하도록 변경했다.
  - 기본 페이지 크기 10, 최대 페이지 크기 100과 입력 범위 검증을 적용했다.
  - 응답에 현재 페이지, 페이지 크기, 전체 메뉴·페이지 수와 첫·마지막 페이지 여부를 추가했다.
  - 잘못된 페이지 값은 `INVALID_REQUEST` 코드와 함께 `400 Bad Request`로 반환하도록 구현했다.
  - API 계약과 기본값·경계값 통합 테스트를 갱신했다.
- 변경 파일:
  - `src/main/java/com/example/cafe/menu/`
  - `src/test/java/com/example/cafe/menu/MenuControllerTest.java`
  - `docs/api/menu.md`

## 검증과 남은 사항

- 실행한 검증과 결과:
  - `./gradlew test`: 성공, 전체 테스트 8개 통과
  - 기본 10개, 마지막 페이지, 최대 100개 조회 확인
  - 음수 페이지, 크기 0과 101의 `400 Bad Request` 확인
  - `git diff --check`: 성공
- 실행하지 못한 검증: 없음
- 남은 제한사항과 사용자 조치: 페이지 번호는 Spring Data 기준에 맞춰 0부터 시작한다.
